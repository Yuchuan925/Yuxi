# Agent 专属 Skill 与现有提示词共存

状态：implemented
类型：feature
Owner：backend/yuxi/modules/extensions/skills/bound.py

## 问题

Agent 的系统提示词适合定义角色、回答要求和简短规则。操作流程、脚本和参考资料需要可编辑的文件包，并在共享、撤权和删除时遵循同一个 Agent 的权限与生命周期。迁移旧版 PR #1064 的功能需要适配 v1 的权限、执行准备和文件修订边界。

## 决策

Agent 可以按需绑定一个专属 Skill。系统提示词继续生效，专属根文件在 Run 准备时自动预加载。普通 Skill 列表、选择项、mention 和依赖候选隐藏绑定资源；绑定内容通过 Agent 入口与直接授权接口读取。专属 Skill 的历史快照遵循[latest 与历史快照决策](./2026-10-04-agent-bound-skill-versions.md)。专属 Skill 的权限与所有权从关联 Agent 派生，不保存独立共享规则，也不提供独立停用、删除或所有权转移。

### 实现方案

`Skill.bound_agent_id` 的 nullable 外键和唯一约束拥有稳定绑定；数据库删除 Agent 时级联删除绑定行。业务 Schema 使用版本 4 的全新部署基线；按 v1 初始化契约拒绝旧版本数据库，不增加旧库兼容路径。绑定创建与上传先锁 Agent，再刷新写入者并锁 Skill；文件编辑沿用相同的 Agent → Skill 锁序；完整编辑使用整包修订保护，既有单文件接口保留文件修订契约。

专属用例位于 Skill 模块的 `bound.py`，Agent 定义的发布、授权变化和删除由 Agent `services/definitions.py` 协调。repository 在用例事务内 flush，service 拥有最终 commit。内容创建、编辑、上传和恢复共用[完整内容提交](./2026-10-05-skill-content-commit.md)：先准备不可变包，再提交当前引用。授权变化在提交前撤下已有投影，提交后按最新范围重建；刷新失败记录日志，运行准备从持久状态重建。删除保留既有活跃执行拒绝，在数据库提交后只清理本次删除已定位的目录。

`/api/agent/{slug}/self-skill` 提供读取和幂等创建，上传子资源接受单 Skill ZIP。读取返回整包 revision，替换在 Skill 行锁内核对目录路径、文件字节与执行位的哈希。单文件或节点变更同步更新整包运行指纹。ZIP 的压缩体限制为 10 MiB，展开限制为 50 MiB、2000 个条目；解析边界拒绝路径穿越、符号链接、特殊文件、无效包和多个 SKILL.md。绑定依赖沿用普通 Skill、工具与 MCP 解析，并校验依赖授权覆盖 Agent 的范围；普通共享 Skill 和其他绑定不能依赖专属 Skill。

worker 从已授权 Run 的 Agent slug 派生绑定，客户端配置不能改写该身份。实际 Context、根内容、Skill metadata 和 manifest 来自同一次准备。执行边界重新授权，保留该 Run 已预加载的专属根文本；中途创建的绑定在下一 Run 加载。脚本和参考文件通过实时用户投影读取，不承诺整包不可变。同一 Run 重试重新准备时沿用 fingerprint 冲突拒绝；后续 Run 包括 steer 和等待恢复读取当前内容。

APP 终端用户的绑定读取复用其 Agent 可见性：按 Key 所属账号的显式范围匹配，并将角色限定为读取。普通 Skill 依赖继续按实际终端用户授权解析。用户投影以 uid 为边界，不构成同一用户不同 Agent 之间的文件保密边界；执行只自动激活当前 Agent 的绑定。

Agent 编辑弹层提供专属 Skill 的加载、失败重试、创建、ZIP 上传与替换确认。文件和依赖编辑复用 SkillDetailView，绑定详情说明权限继承并隐藏独立共享、启停和删除控件。创建时导入与 MCP 创建向导属于后续工作；已有 MCP 与扩展样式能力继续复用当前实现。

## 替代方案

| 方案 | 取舍 |
| --- | --- |
| 只保留系统提示词 | 简短规则无需绑定；不能提供文件包与配套资源 |
| 普通共享 Skill 加命名约定 | 复用文件编辑，但缺少唯一绑定和权限继承约束 |
| 新建专属存储和编辑器 | 重复包校验、目录编辑、投影与修订机制 |
| 稳定绑定并派生权限 | 复用现有文件能力，数据库约束绑定，权限与生命周期需要共同适配；采用 |
| 专属 Skill 替换系统提示词、强制生成 | 改变现有角色配置并制造无需求资产；不采用 |

## 后果

管理者可以维护操作指南与辅助文件，并沿用 Agent 共享范围。根文件增加模型上下文成本，按需创建与短根说明控制这一成本。整包替换拒绝非根文件的并发修改，用户需要刷新、核对后再替换。内容更新沿用运行准备投影机制。未引用目录清理失败记录日志并在后续保存重试；文件系统损坏需要按数据库引用回读并修复。

## 验证

真实 HTTP 集成测试回读数据库和目录，覆盖并发创建唯一绑定、列表隐藏、直接接口权限、ZIP 替换、参考文件修订冲突、包校验失败保留原文件、导出、权限撤销投影失效与删除级联。APP 集成用例验证显式 Agent 授权自动加载绑定、读取上限与跨用户拒绝。集成用例还在真实数据库与目录上注入提交前和提交后失败，分别证明旧引用有效与新提交保持，并验证中途创建绑定延后到下一执行准备。

真实 worker E2E 使用确定性模型协议：Agent 的 skills/preload_skills 均为空，模型仍收到专属根与依赖工具；测试回读 Turn 终态、Run manifest 的预加载哈希、用户投影和删除后的资产。运行中编辑用例通过 replay gate 暂停第一请求后修改根文件，独立模型协议在后续请求拒绝新的根标记，证明同 Run 保留原文与原 manifest；该拒绝 oracle 另有负向单元测试。组件测试验证加载失败重试、ZIP 修订传递和冲突保留当前绑定。具体执行命令、结果和真实页面证据记录在 PR；协议与测试分别由后端 API、集成测试和 E2E 用例拥有。
