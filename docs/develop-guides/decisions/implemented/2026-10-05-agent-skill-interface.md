# Agent 配置与专属 Skill 交互收敛

状态：implemented
类型：simplification
Owner：frontend/src/modules/agents/model/agent.js

## 问题

Agent 接口同时返回数据库 id 和用于路由的 agent_id；前端混用两者导致配置页为空。专属 Skill 入口只展示摘要，保存与发版在全局工具栏重复，默认头像依赖外部服务；私有转共享增加了当前阶段不需要的状态变化。

## 决策

### 实现方案

Agent store 的选择、缓存、创建、更新和删除统一使用 agent_id，数据库 id 保留为持久化身份。专属入口复用只读 Markdown 预览，子组件只发出导航意图；AgentEditModal 在忙碌或存在未保存配置时拒绝跳转，保存后进入统一 Skill 编辑器。文件区域提供一处完整草稿保存，依赖区域提供同一保存入口；历史页只发布已保存内容，未保存草稿阻止发版与恢复。移除全局保存与保存并发版按钮，不引入自动保存。保留 ZIP、文件结构、依赖及历史恢复能力。

本阶段删除私有转共享的 UI、API、service 和 repository 路径，保留已有共享定义及授权框架。专属 slug 固定为 self-UUID8；旧绑定仍按数据库已有 slug 读取，不添加迁移层。最小 Skill 模板使用合法独立占位 slug，绑定提交重写为最终 slug，Agent 标识继续允许下划线。所有 Agent 默认头像入口使用本地确定性 SVG，上传图标优先。窄屏进入现有侧栏收起状态，公共页头和卡片轨道按可用宽度布局；专属详情不再覆盖全局布局样式。配置菜单横向滚动，历史行在手机宽度纵向排列。

## 替代方案

- 保留摘要卡片、外部头像及全局按钮：入口不能直接阅读操作指南，依赖网络并保留重复操作。
- 自动保存后发版：需要额外保存时序与失败语义，当前没有 consumer。
- 仅隐藏共享按钮：后端仍保留未使用的转换流程，不能减少维护面。

## 后果

内容提交、权限、MCP 和执行中的沙盒保持既有 Owner。发版复用历史 API，以完整修订拒绝并发覆盖；文件结构与依赖仍在完整草稿中保存。历史恢复请求与其完整重载共同阻塞编辑、切页和离开，防止重载覆盖新输入。移除发布接口是当前 v1 开发分支的主动收敛，外部调用者需要创建共享定义或维护现有共享定义。

## 验证

用数字数据库 id 与不同 agent_id 的真实 DTO 复现配置空白；验证创建、修改、删除后的缓存与配置结果。真实浏览器检查模型、工具与 MCP 表单、只读预览、文件保存和历史发版，以及浅色、暗色和窄屏布局。HTTP 测试证明私有定义不能转换共享、已有共享绑定仍正确执行授权及撤销；验证新 slug 与历史复用。仓库门禁、独立审阅与最新提交 CI 作为交付证据。


旧能力不存在：搜索当前 UI、API、service、repository 确认不存在私有转共享入口、can_publish 能力及发布实现；文件工具栏不再提供保存并发版。历史日期标识与固定绑定保留。

重新引入条件：只有已确认需求需要私有定义转共享或自动保存时，另行设计转换和失败语义。
